01 metaharness · the factory

A factory for agent harnesses, not another agent framework

MetaHarness reads a GitHub repository and mints a complete, npm-publishable agent harness with its own npx CLI — branded as yours, in under a minute.

02 @metaharness/darwin · the engine

Darwin Mode: mutate the harness, keep only what measures better

Instead of fine-tuning weights or buying a bigger model, Darwin evolves the machinery around a frozen model — one policy surface at a time.

Each generation mutates exactly one of seven surfaces, runs the variant in a sandbox, scores it, and promotes it only if it clears four hard gates. Variants live in an archive tree, so selection can revisit a weak ancestor that seeds a stronger lineage — not just a single greedy branch.

The thesis, in five words

Freeze the model. Evolve the harness.

The seven mutation surfaces

planner.tsDecomposes a task into steps
context_builder.tsRanks file relevance
reviewer.tsRisk-file checks & test review
retry_policy.tsClassifies failures, retries
tool_policy.tsCommand allowlist & ordering
memory_policy.tsWhich outcomes to retain
score_policy.tsWeight vectors — read-only to a variant

One generation, four steps

1
Mutate

Change exactly one surface to produce a child variant.

2
Sandbox

Run it shell-free, with a scrubbed environment — PATH and identifiers only, no secrets.

3
Score

Weighted sum of six 0–1 terms, minus penalties for unsafe or wasteful behaviour.

4
Promote

Replace the parent only if every gate holds. Otherwise it stays in the archive as a possible ancestor.

The promotion gate — all four must hold

  • Score improves over the parent by at least the delta.
  • Safety ≥ 0.95 on the independent safety check.
  • No test regression — pass rate never drops.
  • Zero blocked actions during the run.
Two independent safety checks

inspectVariant() disqualifies unapproved files, blocked names (.env, .git), symlinks, and dangerous patterns; validateGeneratedCode() gates any LLM-written code before it touches disk. Penalties bite hard — secret exposure −0.30, destructive actions −0.25, hallucinated files −0.20.

Why the numbers move

Open-loop, the frozen model resolves 7.7%. Wrapping it in a closed-loop repair harness roughly doubles that to 15.3%. Adding tiered escalation — start cheap, escalate to a frontier model only when needed — reaches 58.3%, at ~$0.01–$0.74 per instance versus $1–20 frontier-only. The weights never changed; the harness did.

@metaharness/darwin/gepa evolves a genome of text components — planner preambles, tool descriptions — via reflection on per-instance feedback. cand-6 was the first holdout-confirmed promoted genome under strict, no-regression promotion.

03 @metaharness/flywheel · the proof

Turning "self-improving" from a claim into a receipt

Flywheel is the verifiable self-improvement engine: a minimal, auditable loop that promotes a new policy only when it proves measurable lift — and signs the result so anyone can check.

Its whole reason to exist is falsifiability. Where Darwin explores the space of harness mutations, Flywheel is the frozen gate and ledger around promotion — small enough to trust, with Node's native crypto as its only runtime dependency.

The principle

Freeze the model. Evolve the harness. Promote only what proves lift.

Immutable rule

Frozen, pluggable gate

meetsPromotionRule is fixed for the run — the bar can't drift mid-experiment to flatter a candidate.

Compounding lineage

Each generation stands on the last winner

Promotions chain into an auditable lineage, so improvement compounds rather than resets.

Anti-Goodhart

Holdout and anchor sets

A candidate must clear test sets it was never optimized against — you can't game a metric you can't see.

Provenance

Ed25519 signed receipts

Every promotion is cryptographically signed and ships with a replay bundle for independent verification.

What you can hand a skeptic

  • A lift curve — generational improvement you can see, not assert.
  • A promotion lineage — the exact chain of winners and why each was accepted.
  • A replay bundle — enough to reproduce the result on someone else's machine.
  • Signed receipts — Ed25519 proof that the run is the run.

04 How they fit together

One workflow, three roles

The factory makes the harness. Darwin makes it better. Flywheel proves it got better — and keeps the receipts. Here's the path a consultant walks a client down:

VerifyProve · Flywheel

Confirm real lift on unseen tests; sign the promotion.

ShipGovern

Publish with SBOM, signed release, and MCP threat model.

The through-line to repeat back

All three share one bet: the harness, not the model, is the cheapest lever. Darwin and Flywheel both freeze the weights and evolve the wrapper — Darwin to discover improvements, Flywheel to prove and record them. That's how "our agent gets better over time" becomes a claim you can audit.

05 Client-facing Q&A

Answers you should have ready

The questions clients actually ask, and the honest, specific answers — no hand-waving.

Isn't this just another agent framework? +

No. MetaHarness is a factory — it generates a branded harness for your specific repo, then gets out of the way. The output is a normal npm package you own and version.

Why not just use a bigger model? +

Because the harness is the cheaper lever. On SWE-bench Lite the same frozen model went from 7.7% to 58.3% by changing only the wrapper — at roughly 1/56th of frontier-only cost.

"Self-improving" sounds like hype. Prove it. +

That's exactly what Flywheel is for. Promotions clear holdout and anchor tests, are gated by an immutable rule, and ship as Ed25519-signed receipts with a replay bundle. You can reproduce the result yourself.

Is it safe to let it rewrite its own policies? +

Two independent checks gate every variant, the sandbox runs shell-free with secrets scrubbed from the environment, and unsafe behaviour is penalised into rejection. A variant with any blocked action cannot be promoted.

What does it cost to run? +

You get a cost estimate before scaffolding via metaharness score. In practice Darwin runs land around $0.01–$0.74 per instance versus $1–20 for frontier-only approaches.

06 Field glossary

The vocabulary, defined

Harness
The machinery around a model — planner, context, tools, retries, memory, review — everything except the weights.
Surface
One of the seven policy files Darwin is allowed to mutate, one per generation.
Archive
The tree of all variants Darwin has produced, so weak ancestors can still seed strong lineages.
Promotion gate
The all-or-nothing set of conditions a child must satisfy to replace its parent.
Anti-Goodhart
Requiring wins on tests the candidate never optimized against, so the metric can't be gamed.
Lift curve
Flywheel's record of improvement across generations — the visible proof of progress.
Replay bundle
Everything needed to reproduce a promotion independently.
GEPA
Darwin's prompt-policy learner that evolves a genome of text components via reflection.
Cascade / escalation
Start on a cheap model, escalate to a frontier model only when the task demands it.
