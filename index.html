The big idea

Why the smartest move in agents right now is to stop chasing bigger models.

01.1 The problem

Every repo wants a repo-aware agent — and every agent burns money

A generic assistant doesn't know your codebase, your funnel, or your data. Hand-tuning one is slow and doesn't stick. And the obvious fix — reach for a bigger model — is the expensive one, precisely where agents live longest.

  • Context gap — off-the-shelf agents have no idea how your system actually works.
  • Cost gap — in a long-running app, LLM tokens are the single biggest line item.
  • Trust gap — "it gets better over time" is usually an unfalsifiable claim.
The three gaps a harness has to close

Don't buy a bigger brain. Build a better harness around the one you have.

the MetaHarness thesis

The model's weights stay frozen. Everything around it — how it plans, what context it sees, which tools it may call, when it retries, what it remembers — is the harness. That's the part you evolve, and it's cheap to change.

Frozen core, evolving harness

01.3 Why the harness is the cheapest lever

Cheapest capable model, best possible answer

The edge isn't only that it's smart — it's that it's the cheapest route to the best answer. Small model where it suffices; escalate to a frontier model only when a task truly needs it.

From a repository to a publishable agent — in under a minute

PART 03

Darwin — the engine

"Freeze the model, evolve the harness" — made mechanical.

seven surfacesarchive treescore & gatethe lift

03.1 @metaharness/darwin

Evolve the operating system around a frozen model

One policy surface mutates per generation. Each variant runs in a sandbox, gets scored, and is promoted only if it clears four hard gates — so improvement is measured, never assumed.

Validated on real SWE-bench bug-fixing — not a toy loop. Latest: v0.8.0, MIT © rUv.

"Out of a hundred evolutions, this is the best one. The ones that work, it evolves more. The ones that don't are dead ends."

Reuven Cohen

03.2 The seven mutation surfaces

Exactly one changes per generation

Isolating a single change keeps the causal signal clean — you know precisely which surface moved the score, and by how much. Six are writable by a variant; score_policy is read-only, so a variant can't grade its own homework.

Why one at a time

Change two things and a win is unattributable. Darwin trades speed for a clean gradient.

03.3 The archive tree

Not a greedy climb — a population

Variants live in an archive tree, not a single best branch. Selection can revisit a weaker ancestor that turns out to seed a stronger lineage — exactly like biology, where a dead end for one trait is the origin of another.

  • Keeps "losers" around — a low scorer may carry a mutation that pays off later.
  • Opt-in strategies — quality-diversity, Pareto selection, crossover, MAP-Elites.
  • Reproducible core — every extra is a toggle over a frozen, seeded baseline.
A weak ancestor can seed the winner

03.4 One generation, four steps

The generation loop
  • Mutate — change exactly one surface → a child variant.
  • Sandbox — run it shell-free, secrets scrubbed from the environment.
  • Score — six 0–1 quality terms, minus penalties.
  • Promote — replace the parent only if every gate holds; else keep it as an ancestor.

Everything lands in .metaharness/

  • archive.json · lineage.json — the population & its graph
  • runs/ · reports/winner.json — traces, scores, the best result

03.5 The scoring model

Reward the outcome, punish the risk

A base score — the weighted sum of six 0–1 quality terms — minus a penalty layer that makes unsafe or wasteful behaviour uncompetitive by construction. A variant literally can't win by cutting a dangerous corner.

  • Six quality terms feed the base score.
  • Five penalties subtract for risk & waste.
  • Net score is what the gate compares.
Base score, minus penalties (labeled)

Penalties: secret exposure −0.30 · destructive −0.25 · hallucinated files −0.20 · tool loops −0.15 · cost overrun −0.10.

03.6 The promotion gate

Four gates. All must hold, or the parent stands.

This is what turns "it improved" into a fact rather than a vibe — a promotion is a claim with four preconditions, checked every time.

  • Score improves over the parent by at least the delta.
  • Safety ≥ 0.95 on the independent check.
  • No regression — test pass rate never drops.
  • Zero blocked actions during the run.
Many variants in · few promoted out

03.7 The safety model

Two independent checks, before code ever runs

Letting a system rewrite its own policies only works if it can't rewrite them into something dangerous. Darwin gates every variant twice, then runs it with no shell and no secrets.

Belt and suspenders

Static inspection catches the file; code validation catches the payload; the sandbox contains the blast radius; the score penalizes the attempt. Four layers, any one of which stops a bad variant.

  • inspectVariant() — disqualifies unapproved files, blocked names (.env, .git, secret), symlinks, and dangerous patterns (eval, fetch, child_process).
  • validateGeneratedCode() — gates any LLM-written code before it touches disk.
  • Shell-free sandbox — no command injection; a scrubbed env exposes only PATH + identifiers, never secrets.
  • Score penalties — even a variant that slips through loses on the scoreboard.

Flywheel — the proof

Turning "self-improving" from a claim into a receipt.

04.1 @metaharness/flywheel

Perpetual motion — and a receipt for every gain

Darwin finds the cheapest, best model for a task. The Flywheel asks the best process — running continually, rewriting its own code, promoting only what proves measurable lift.

v0.1.7 · ESM, fully typed · runtime dependency: Node's native crypto, nothing else.

The loop that never stops

04.2 Four properties that make it trustworthy

immutable rule

Frozen gate

meetsPromotionRule can't drift mid-run to flatter a candidate.

compounding

Lineage

Each generation builds on the last promoted winner — season over season.

anti-Goodhart

Holdout + anchor

Must win on test sets it was never optimized against.

provenance

Ed25519 receipts

Signed promotions ship with a replay bundle.

Why "minimal" is a feature

Small enough to trust and audit end-to-end — one runtime dependency, a frozen gate, and a signed trail. The whole point is that a skeptic can read it and reproduce it, not take your word.

04.3 Anti-Goodhart construction

You can't game a metric you can't see

"When a measure becomes a target, it ceases to be a good measure." Flywheel defuses that: a candidate is optimized on one set but must prove itself on others it never touched.

  • Holdout set — unseen during optimization; catches overfitting.
  • Anchor set — a fixed reference that guards against silent regressions.
  • Clear both, or no promotion — a lucky run on the training slice isn't enough.
Optimize on one, prove on two

04.4 What you hand a skeptic

  • A lift curve — improvement you can see, not assert.
  • A promotion lineage — the chain of winners, and why each passed.
  • A replay bundle — reproduce the result on another machine.
  • Signed receipts — Ed25519 proof the run is the run.

Darwin explores the space of harnesses; Flywheel is the frozen gate and signed ledger around promotion. You need both — discovery without proof is a guess; proof without discovery has nothing to promote.

"Why not just use a bigger model?"
